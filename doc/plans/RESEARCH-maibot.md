# MaiBot 参考调研（2026-10-12）

> 对象：`reference/MaiBot`（commit 0f94cfa8，2026-10-12）。Python，约 600 个源文件，**GPL-3.0**。
> 规则：**只借鉴思路，不复制代码**（含 prompt 原文）。以下均为用我们自己的话复述的设计思想。

## 1. 值得借鉴（按价值排序）

### 1.1 用数据“蒸馏”出来的开口概率门（`src/maisaka/turn_trigger/reply_likelihood.py`）
- 没被 @ 时，先用一个**逻辑回归**估计“如果交给大模型判断，它会回复的概率”，概率低就不调用大模型。
- 特征只有 8 个，都能零成本算出：是否提到 bot 名字、是否 @ 了别人、是否有问号、是否只有图片/表情、**最近 5 分钟 bot 自己发言的占比**、最近 5 分钟消息数、距 bot 上次发言的秒数（取 log）、本批新消息条数。
- 权重是用**大模型过去的真实判断记录拟合**出来的（离线脚本），被 @ 的消息不经过这个门。
- 其中“最近 bot 自己发言占比”权重最大（约 2.65）——和 ai-bot-groupmate 的“活跃期提权”结论一致。
- **对我们**：我们的 `decisions` 表已经在记录每次判断。M2 先用 `judge` 模型判断并积累数据，之后离线拟合出自己的逻辑回归门，替换掉手写规则。这是很好的面试点：“把 LLM 的判断蒸馏成零成本的线性模型”。

### 1.2 按目标频率动态调整阈值（`turn_trigger/dynamic_gate.py`）
- 用户设一个“说话频率”系数（`talk_value`）。系统统计过去 1 小时内“不设门槛时预计会回几次”和“实际回了几次”，自动调整概率阈值，让实际次数 ≈ 预计次数 × 频率系数。数据不足时用离线统计的静态阈值表。
- **对我们**：四种活跃模式（积极 / 自然 / 忙碌 / 只在被叫时）可以落地为**目标频率**，而不只是提示词里的一句描述。行为可预期、可量化，也方便评测。

### 1.3 空闲退避（`turn_trigger/idle_backoff.py`）
- 连续几轮判断都是“不回”之后，下一次判断前的等待时间指数增长（默认从 15 秒起，封顶 300 秒，连续 2 次后开始）；新消息积累到一定条数则跳过等待。
- **对我们**：“自然”模式“每条都看”时，用它显著减少 `judge` 调用次数。

### 1.4 回复效果追踪（`src/maisaka/reply_effect/`）
- bot 每发一条回复，就在之后 30 分钟 / 最多 15 条后续消息内观察群友的反应。
- **归因**：引用了 bot 那条消息 = 高可信；只是语义上相关 = 按“同一条消息可能指向几条 bot 回复”的歧义程度打折。
- **分类**（由评审模型输出）：
  - 群友的态度：欣赏 / 玩闹 / 中性 / 困惑 / 纠正事实 / 拒绝 / 攻击 bot；
  - bot 这条回复对对话的作用：推进 / 维持 / 附和 / 收尾 / 推错方向。
- **评分**：确定性公式，考虑有没有人回应、有几个人回应（广度）、回应了多少（深度）。
- 记录每次回复的**提示词指纹**，便于把效果归因到某一版提示词。
- **对我们**：
  - 这正是 DESIGN §9.3“根据真人实时反馈判断 bot 之间的对话是否继续”需要的结构化信号，比我们现在“正信号 / 负信号”的粗列表好得多；
  - 也是 §13“线上反馈回流评测集”的现成方案；
  - 决策记录里加上提示词指纹，评测时就能对比不同版本提示词的效果。

### 1.5 表达方式学习与黑话学习（`src/learners/`、`maisaka/jargon_context_matcher.py`）
- **表达方式**：定期从群聊中提取“在 A 情境下，可以用 B 说法”的规则（不学 bot 自己的发言、不含人名和具体名词、每条规则带来源消息编号），存库，回复时按情境挑选合适的几条放进提示词，并有一个模型审核步骤。
- **黑话**：先提取“脱离本群语境就看不懂”的候选词（拼音缩写、英文缩写、中文缩写、群内反复出现的短语），再结合上下文推断含义；聊天中出现这些词时，把解释注入上下文。
- **对我们**：DESIGN 里“像群友”目前只靠人设卡，缺少“学群友说话”这一块。建议加入 M2（表达方式）和 M3（黑话）。学到的内容同样要走记忆写入门槛与私密分级（私聊里学到的不用于群聊）。

### 1.6 注意力漂移（`src/maisaka/attention_drift.py`）
- 用三个可调档位描述“跳脱程度”，渲染成提示词里的一段规则：
  - 漂移档位：轻微 / 活跃 / 发散 / 强烈跳跃；
  - 回钩策略：严格 / 自然 / 宽松（联想之后要不要回到正题）；
  - 短反应风格。
- **对我们**：可以作为人设卡之外的**性格旋钮**，在控制台用滑块调。与活跃模式正交：模式决定“多常说话”，漂移决定“说话多跳脱”。

### 1.7 其他小点
- 人物画像注入有明确预算：每次最多注入 4 个人、总计约 900 字。我们的画像注入可以先用同样量级的上限。
- 召回长期记忆前，先让模型用一段自然语言概括“这段对话此刻的整体印象”，再用这段话去检索记忆，而不是用关键词。
- 提示词全部放在独立的模板文件里（并维护多语言版本），不写死在代码中。建议我们也把提示词放到 `prompts/` 目录，便于在控制台编辑、做版本指纹。
- 按时间段调整说话频率的规则（`talk_value_rules`）——与 DESIGN §5.1“按时间段切换模式”一致。
- 工程上：事件循环卡顿看门狗；会话 ID 只允许由会话管理模块解析，其他模块不得自行计算。

## 2. 不建议借鉴
- **规划器 + 工具的 agent 循环架构**：MaiBot 由一个规划器模型通过工具（回复、等待、发表情、查记忆、查人物画像、翻历史……）自主决定每一步。灵活，但每轮都要调用大模型，成本和延迟更高，也更难控制。我们坚持“确定性流水线 + 只在判断和生成两处调用模型”。不过，其中“查记忆 / 查人物画像作为按需工具”的思路，以后可以在 `reply` 阶段作为可选项。注意：工具式召回会绕过私密信息守门，必须让工具也经过守门。
- **体量**：`runtime.py`、`reasoning_engine.py` 都超过 2000 行，是我们要避免的巨石文件。
- **任何代码与 prompt 原文**：GPL-3.0，复制会导致我们的项目也必须以 GPL 发布。

## 3. 建议并入 DESIGN 的改动（待用户确认）
1. §5 活跃模式：模式 = 目标说话频率（动态阈值）+ 空闲退避；“规则粗筛”在积累足够数据后由拟合的逻辑回归门替代。
2. §9.3 与 §13：采用“回复效果追踪”的结构（观察窗口、归因可信度、态度 / 作用分类、确定性评分、提示词指纹）。
3. M2 新增“表达方式学习”，M3 新增“黑话学习”。
4. M2 新增“注意力漂移”性格旋钮。
5. 提示词放入 `prompts/` 模板文件；决策记录增加提示词指纹字段。
