- 已有主人专用指令通道：`src/core/conversation/management.ts`（`/aq ping|mute|unmute|recall|status`，用 `config.owner` 判身份）。

### 常用表情 bug 的根因

`persona-import.md` 只给了字段名 `"常用表情":[]`，没有定义。中文「表情」既是 sticker/emoji，也是脸部神态，flash 模型选了后者，于是把「脸红到耳根」「低头玩手指」这类**神态与小动作**塞了进去。同一张截图里还有冗余：「面对他人：冷淡、简短、礼貌而疏离」同时出现在 说话方式 和 对陌生人。两个问题都是提示词缺字段定义 + 没有去重/覆盖检查造成的。

## A. 一次性任务：放宽预算，换严格流程

适用：人格导入、聊天记录导入并分析（以后的「导入世界观」等同理）。一年只跑一两次，宁可贵一点也要对。

### A1. 新槽位 `oneoff`

- `config.example.yaml` / `data/config.yaml` 增加 `slots.oneoff`，默认指向 reply 链的强模型（如 `deepseek-v4-pro`，`reasoning: high`，`maxTokens` 8000，`timeoutSec` 240），链尾可降到 flash。
- 人格导入从 `extract` 改走 `oneoff`。聊天记录导入在确认弹窗加「精细分析（用 oneoff 槽，约 ¥x）」开关，默认关。

### A2. 预算口径

- 一次性任务由主人在面板手动点击触发，**不受日预算拦截，也不计入聊天日预算**（否则导入一次可能让她当天闭嘴）。用量表记 `slot='oneoff'`，用量页单独一行。
- 换成**单任务上限** `budget.oneoffTaskCny`（默认 3）：开跑前按输入长度估算并在确认框显示；运行中累计超过上限就停在当前回合，返回已有结果 + 原因。
- 与 R1.1 的关系：R1.1 落地时，`callSlot` 增加 `budgetScope: 'daily' | 'oneoff'` 选项，`oneoff` 走单任务上限而不是日上限。R1.1 本身照常做（顺手在本计划第 1 步一起做掉）。

### A3. 人格导入改成「抽取 → 代码检查 → 修复」小循环（最多 2 轮修复）

1. **字段说明书**：在 `prompts/persona-import.md` 里给每个字段写「是什么 / 不收什么 / 一个例子」。关键几条：
   - `常用表情`：聊天里会**发出去**的东西——QQ 小黄脸名、emoji、颜文字、表情包风格（如「猫猫表情包」「熊猫头」）。**不收**脸部神态、肢体动作、生理反应。
   - 新增可选小节 `神态与小动作`（走 other 的固定 heading，不改 schema 必填项）：脸红、低头玩手指、呼吸停住这类。它们以后可以给心声/反应表用。
   - `说话方式`只写语言层面（人称、语气、句式、口癖规律）；对某类人的态度写进 `对熟人/对陌生人/对主人`，**同一句不得两处都写**。
2. **带出处**：输出 JSON 每个条目带 `src`（原文中的一段连续原句，≤40 字）。schema 改为 `{"text": "...", "src": "..."}`，入库前剥掉 `src`。
3. **代码检查**（不花钱）：
   - 每个 `src` 必须能在原文里找到（归一化空白后子串匹配）→ 否则判「编造」。
   - 原文按段落/句号切块，每块至少被一个 `src` 覆盖或进了 other → 否则判「缺漏」，列出未覆盖的原句。
   - 跨字段重复（同一 `src` 或 text 相似度 > 0.8）→ 判「冗余」。
   - 已知易错规则：`常用表情` 条目若含「脸/耳/手指/低头/呼吸/身体」等词且不含表情包/emoji 特征 → 判「放错字段」，建议挪到 神态与小动作。
4. **修复回合**：把检查结果作为一条 user 消息发回（「以下 3 句未覆盖：…；常用表情第 2 条是神态，请移动」），要求输出完整修正版 JSON。最多 2 轮，仍不过就带着警告返回草稿，面板上把有问题的条目标黄。
5. 结果面板显示：映射数、other 数、修复了几处、剩余警告。

### A4. 聊天记录「分析」

`extract-tags` 现行流程保持；精细模式只换槽位 + 窗口加大到 200 条 + 同样的「出处必须存在」检查（tag 的 evidence 必须是窗口里真实的消息 id）。不在本计划里重写标签体系。

## B. 在对话里改自己的设置

### B1. 谁能用、在哪用

- **只有主人**（`message.senderId === config.owner`，owner 为 0 时整个功能关闭）。
- 默认**只在私聊**生效；群里主人说「把口头禅改了」也只回一句「私聊跟我说」。（待定 ①）
- 配置开关 `selfEdit.enabled`（默认 true）+ `selfEdit.scopes`（下表的哪几组开放）。

### B2. 怎么触发（不让每条消息都多花钱）

1. 主人私聊消息先过一个**零成本关键词预筛**（改/换/设置/以后别/以后要/调高/调低/口头禅/称呼/作息…）。
2. 命中再用 `judge` 槽做一次极短分类：`{"intent":"settings"|"chat"}`。
3. `settings` → 进入 B3 的小 agent loop；`chat` → 正常回复。
4. 显式入口也保留：`/aq set <自然语言>` 直接进 loop，跳过分类。

### B3. agent loop（provider 无关的 JSON 动作协议，不依赖原生 tool calling，CLI 槽也能跑）

新文件 `src/core/self-edit/`：`loop.ts`、`tools.ts`、`registry.ts`、`pending.ts`，提示词 `prompts/self-edit.md`。

- 每轮模型只能输出一个 JSON 动作：
  - `{"action":"read","key":"persona.口头禅"}` → 返回当前值
  - `{"action":"propose","changes":[{"key":"…","op":"set|add|remove","value":…}],"say":"给主人的一句话（人设口吻）"}`
  - `{"action":"ask","say":"…"}`（意思不清时反问一次）
  - `{"action":"refuse","say":"…"}`（不在白名单里）
- 最多 4 轮，用 `oneoff` 槽还是 `reply` 槽：用 `reply` 槽（频率不算低，没必要用最贵档）。（待定 ②）
- 白名单与 zod 校验在代码里，模型给的 key 不在 registry 里直接拒。

### B4. 能改什么（registry）

| 组 | 例子 key | 默认 |
|---|---|---|
| 人设·待人接物 | 口头禅、常用表情、说话方式、对主人、按对象称呼（对主人的称呼） | 开 |
| 人设·性格 | 性格四维滑杆（每次最多 ±1 档） | 开 |
| 人设·底线 | 只能 **add**；remove 需在面板操作 | 开（只加） |
| 行为参数 | 作息时段、主动搭话频率、表情包发送频率、贴表情开关 | 开 |
| 会话 | 本群闭嘴 N 分钟（已有 mute） | 开 |
| **永不开放** | 模型/服务商/密钥/价格/预算、owner、隐私等级与 policy、账号绑定、他人的印象与记忆删除、prompt 模板 | — |

### B5. 确认与撤回

- `propose` 之后**不立即写**：她用人设口吻复述 + 机器可读的 diff，例如
  「要把口头禅加上『哼』，再把『抱……抱月……』去掉。可以吗？」
  下面附一行灰字式的精确描述：`口头禅 +「哼」 −「抱……抱月……」`。
- 主人回「好/可以/确认/嗯」（关键词，不走 LLM）→ 写入；回别的 → 视为取消；10 分钟不回 → 过期。
- 写入走现有保存路径（人设走 `recordPersonaVersionOnSave`，参数走 `config/write.ts`），所以面板「版本」页能看到并回滚；事件簿记一条「来自对话的设置修改」。
- 主人说「撤回刚才的修改」→ 回滚到上一版本（同样要确认一次）。
- 人设改动要等热加载还是重启：沿用现状，若需重启，确认句里说明「下次重启后生效」。

### B6. 风险

- 提示注入：只认 owner 的 senderId，群消息、转发、引用里的文字一律不触发；registry 白名单兜底。
- 人设漂移：性格每次 ±1 档、底线只加不删、所有改动有版本可回滚。
