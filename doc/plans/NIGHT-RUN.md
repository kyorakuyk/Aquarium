# 夜间无人值守运行规则（覆盖 HANDOFF.md 中与之冲突的条款）

> 适用：用户睡觉期间，无人可以回答问题、无人可以在 QQ 上做验证。
> 读完 `HANDOFF.md` 与 `DESIGN.md` 后再读本文。本文优先级高于 `HANDOFF.md`。

## 1. 范围
- 只做 `HANDOFF.md` 中 **T0 → T6** 的**代码与单元测试**部分，按顺序。T6 之后**停止**，不做 T7 及以后。
- 所有标 **【用户】** 的验收步骤：**不执行**，改为写进 `doc/plans/MORNING.md`（格式见 §4），然后继续下一个任务。
- T0 的完成标准改为：修补脚本完成、`npm run typecheck` 通过、`node -e "import('@snowluma/sdk').then(m=>console.log(Object.keys(m).length))"` 输出数字。

## 2. 遇到问题时
- `HANDOFF.md` 里“不确定就停下来问用户”在夜间改为：
  1. 把问题、你考虑过的选项、你选择的做法写进 `MORNING.md` 的「待确认问题」；
  2. 选**最保守、最容易回退**的做法继续；
  3. 如果某个任务的核心前提无法满足（例如 `node:sqlite` 在本机 Node 上不可用），**跳过该任务及依赖它的任务**，记录原因，继续做不依赖它的任务；若剩下的任务都依赖它，就结束本次运行。
- 同一个错误修了 3 次仍失败：停止该任务，记录完整错误信息，按上一条处理。

## 3. 禁止（夜间额外）
- 不运行 `npm start`、任何 `src/spike/*.ts`、任何会发出真实大模型请求或连接 SnowLuma 的命令。
- 不访问网络，`npm install` 安装 HANDOFF §3 列出的库除外。
- 不修改仓库目录 `E:\Teamworks\Aquarium` 以外的任何文件；不修改全局 npm / git / 系统配置。
- 不在 `main` 分支上提交。

## 4. Git 与记录
- 开始前：`git switch -c night/2026-10-12`（若已存在则切换过去）。所有提交都在这个分支上，每个任务一次提交。
- 维护 `doc/plans/MORNING.md`，结构固定为：
  ```
  # 早上检查清单
  ## 完成情况        （每个任务一行：编号 / 状态 完成|跳过|失败 / 一句话说明 / 提交哈希）
  ## 需要用户操作的验证 （按任务列出 HANDOFF 中的【用户】步骤，写成可直接照做的编号步骤）
  ## 待确认问题        （问题 / 考虑过的选项 / 夜间采用的做法）
  ## 遇到的错误        （任务 / 命令 / 关键报错 / 已尝试的修复）
  ```
- 每完成一个任务就更新一次 `MORNING.md` 并随该任务一起提交，保证即使运行中途中断，早上也能看到进度。

## 5. 结束条件（满足任一即结束，并做最后一次提交）
- T6 代码与测试完成；
- 剩余任务全部被阻塞；
- 运行时间达到 9 小时。
